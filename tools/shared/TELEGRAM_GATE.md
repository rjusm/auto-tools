# Telegram-уведомления и остановка (общие правила)

Используется скиллами `slow-query-fix` и `incident-triage` (и любыми следующими с похожим потоком). Один скрипт, один бот — настраивается один раз.

Скрипт: `python -I tools/shared/tg_gate.py {notify|gate|check} ...` (путь — от корня проекта; подробности в самом файле).

Настройка (один раз, делает пользователь): создать **отдельного** бота в @BotFather (боевых ботов проекта не использовать — `getUpdates` конфликтует с их обработчиками и они пишут в рабочие чаты), написать ему, и положить в `tools/shared/.env.local` (вне репозитория):
```
SLOWQUERY_TG_TOKEN=...
SLOWQUERY_TG_CHAT_ID=...
```
Токен не печатать в чат/логи и не коммитить. Реагирует только на пользователя из `SLOWQUERY_TG_USER_ID` (по умолчанию = chat id). Имя переменных осталось `SLOWQUERY_*` по историческим причинам — бот общий для всех скиллов, не только для slow-query-fix.

Правила:
- В **начале** и **на каждом значимом этапе** скилла — `notify` с коротким итогом (что сделано, ключевые цифры).
- Нумеруй прогресс: после первого шага анализа, когда понятен примерный план, оцени общее число уведомлений/gate до конца и передавай `--step N/M` в каждый `notify`/`gate`, увеличивая N. Число M — ориентир, а не контракт: если по ходу добавился/пропал этап, просто поправь M в следующих вызовах.
- Форматирование текста (как у типичных CI/CD/деплой-ботов в Slack/Discord/Telegram — короткий статус жирным/эмодзи сверху, код отдельным блоком): начинай текст с эмодзи-статуса, по смыслу этапа — ▶️ старт, 🔎 анализ/поиск источника, 💡 решение, 🧪 воспроизведение/замеры, ✅ готово/успех, ⚠️ предупреждение, 🛑 только в сообщениях про стоп (их шлёт сам `tg_gate.py`, вручную не нужно). Одно-два слова, не перегружай. Код/идентификаторы — в бэктиках (`` `table` ``, `` `column` ``, `` `--flag` ``) — рендерится моноширинным. SQL/PromQL/LogQL, EXPLAIN, диффы, вывод команд длиннее одной строки — в тройных бэктиках (можно с языком, ```` ```sql ... ``` ````) — рендерится отдельным блоком, а не прилипает к остальному тексту.
- Для табличных данных (метрики до/после, объём/время/EXPLAIN, breakdown по строкам) — используй `--rich` у `notify`/`gate`: он шлёт через `sendRichMessage` (Bot API 10.1+, появился в 2026), который поддерживает настоящие таблицы через GFM-markdown — проверено живым вызовом, реально рендерится как таблица, а не моноширинный текст:
  ```
  python -I tools/shared/tg_gate.py notify --rich --step N/M '
  | Метрика | До | После |
  |:--------|---:|------:|
  | Время   | 1850ms | 12ms |
  | rows    | 2.9M | 52 |
  | Extra   | filesort | — |
  '
  ```
  Важно: `--rich` отправляет текст **как есть**, без HTML-экранирования и без ```-конвенции обычного `notify`/`gate` — сам текст уже должен быть валидным markdown (учитывай, что `*ـ\`|[]~=` в обычном тексте — спецсимволы разметки). `--step` в `--rich`-режиме оборачивает префикс в `**[N/M]**` (markdown bold), а не HTML. Обычный режим (без `--rich`) по-прежнему годится для короткого текста и однострочного кода — переключайся на `--rich` конкретно ради таблиц/заголовков/списков.
- Перед этапами, которые что-то меняют в коде/БД/репозитории или долго идут, — `gate` с кнопками «Продолжить / Пропустить этап / Стоп». Какие именно шаги гейтить — определяет конкретный SKILL.md (обычно: выбранное решение, наполнение данными/долгая операция, применение правки/миграции, создание ветки/коммита/push).
- Коды выхода: `0` — продолжить; `12` — пропустить этап; `10` — **СТОП**; `11` — таймаут (= стоп); `2` — ошибка настройки/сети (= стоп, сообщи пользователю в чат, что Telegram недоступен, и спроси, как продолжать).
- Код `2` означает, что `tg_gate.py` уже сам повторил запрос (до 3 попыток с задержкой) и всё равно не достучался до Telegram — это не разовый сетевой сбой, повторять вызов вручную смысла нет; сообщи пользователю и жди его решения.
- При `10`/`11`/`2` немедленно прекрати работу: не запускай следующих шагов, останови фоновые процессы, которые сам запустил, и скажи в чате, на каком этапе остановились и в каком состоянии рабочее дерево/БД. Ничего не откатывай и не удаляй без вопроса.
- Долгие шаги (наполнение данными, ALTER, долгие запросы к мониторингу) запускай в фоне и каждые 1–2 минуты вызывай `check`; если вернул `10` — останови процесс. Пользователь может остановить в любой момент кнопкой «Стоп» или сообщением `/stop` / `стоп`.
- В уведомления не включай данные клиентов, значения параметров из прода и секреты: только структуру, имена, цифры времени/объёма.
- Если Telegram не настроен (код `2` при первом вызове) — предупреди пользователя один раз и работай без уведомлений только если он согласится; gate-шаги тогда подтверждай в чате.
